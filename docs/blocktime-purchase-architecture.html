Phase 10 · Top Up & Renewal Flow
📊 Pilot clicks [Top Up] from dashboard or renewal email CTA
Same package selection UI. Current balance + expiry shown. Pilot selects same or larger package tier.
↓
⚡ New Stripe PaymentIntent created for top-up amount
On success: new pilot_block_time_purchases record created. If existing package still active → FIFO queue (new package activates after current exhausted). If expired → activates immediately. New invoice generated: OZ-2026-NNNNN.
Phase 11 · Refund Flow
💸 Pilot requests refund on unused Block Time hours
System calculates: hours flown from this package × $330/hr (standard rate).
Refund = amount paid − recalculated cost at $330.

Example: 50h @ $300 = $15,000 paid. Flew 20h. Recalc: 20h × $330 = $6,600. Refund = $8,400.

Refund summary shown to pilot before they confirm request.
↓
🔧 Admin reviews & approves refund
Admin sees refund request in queue with full calculation breakdown. Approves → Stripe refund API fires for calculated amount. Package status → refunded. New credit note invoice created referencing original invoice number.
